# FIGMA STATES — NOT COUNTED AS SEPARATE PAGE NUMBERS

The **230 pages above are the core page/screen inventory**.

For applicable screens, the Figma prototype will additionally contain:

**Normal State**

Standard page with content.

**Loading State**

Skeleton cards, table skeletons, loading indicators and progressive loading.

**Empty State**

Examples:

No products  
No orders  
No messages  
No vendors  
No notifications  
Empty cart  
Empty wishlist  
No reviews  
No search history

**No Results State**

Especially for search, categories and filtering.

**Error State**

Failed API call, failed payment, failed upload, failed product retrieval and general network error.

**Success State**

Product added to cart, order created, profile updated, product published, vendor approved, etc.

**Disabled State**

Unavailable actions and controls.

**Unauthorised State**

User attempts to enter a protected route without authentication.

**Permission Denied State**

For role-based access restrictions.

**Suspended / Restricted State**

Particularly vendors, customers and administrators.

**Offline State**

Connection unavailable.

# DESIGN ORDER

We should **not** randomly create these 230 screens.

We should build them sequentially so shared components become consistent throughout the project.

Our actual design work should start with:

**Page 1 — Landing Page**

Then:

**Page 2 — Shop All Products**

**Page 3 — Search Focus**

**Page 4 — Search Results**

**Page 5 — Advanced Search**

…and continue using the numbering above until the complete platform has been designed.

The same page number should remain attached to a screen for the entire project so that, for example, when we later say:

> “Change the sidebar on Page 150”

we immediately know that we are discussing the **Admin Dashboard Overview**.
